## 本轮范围

按审阅建议优先解决三个问题：新用户必须先启动客户端形成实例才能发布服务；服务目录检查不能声称已经验证连接；HTTP 发布必须明确访问范围。

## 验收

- [x] 帮助使用实际界面名称和正确顺序：下载 → 创建接入凭证/保存配置 → 启动并等待上线 → 发布服务 → 手动验证访问。
- [x] 接入页提供明确步骤和下一步操作；加载失败不被当作尚无设备。已注册设备默认收起完整引导，可随时展开。
- [x] 创建凭证后提供包含接口返回 apiKey/secret 的 client.jsonc；页面内敏感内容不写入浏览器持久存储，关闭时清除。复制和下载只在用户主动操作时执行。
- [x] 发布表单没有客户端时给出接入入口，不能产生无目标请求。
- [x] Peer 服务操作改为“检查目录状态”，展示检查时间、实际结果和下一步；共享关闭或读取失败后仍可检查，成功恢复清除旧错误；不发起目标连接测试。
- [x] HTTP 新建默认受保护，明确选择受保护/公开访问并展示访问范围摘要；公开创建必须再次确认。
- [x] 编辑从受保护改为公开时必须确认，取消不写入且保留原认证配置。
- [x] 现有已公开路由不被自动改写，现有访问密码保留规则不变。
- [x] 单测、类型检查、生产构建及隔离浏览器回归通过。
