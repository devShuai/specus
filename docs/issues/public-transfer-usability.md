# 互传页面易用性与概念一致性修复

跟踪：https://github.com/devShuai/specus/issues/36

状态（2026-09-06）：修复与本地验收完成，提交及推送记录见关联 issue；尚未部署，issue 保持开启以跟踪发布。

## 目标

让用户始终清楚内容发给谁、哪些操作会发送、对方是否收到，以及文件是否已交给浏览器保存。保留已有直连、TURN、临时文件链接和协作能力，不扩展到后台其他模块。

## 验收清单

- [x] 白板与流程图只与明确加入同一协作空间的成员同步；附近发现不自动赋予协作资格，收发双向过滤。
- [x] 设备操作只保留单设备动作；多人白板独立展示成员范围与邀请入口。
- [x] 不自动选择第一台设备，不在原目标离线时自动换人；固定展示当前发送对象。
- [x] 文字默认粘贴/读取为草稿，显式发送；可主动开启粘贴即发送，“文字与链接”内的文件粘贴也遵守该选择。文件页仍明确标示选取、拖入或粘贴即发送。
- [x] 分享文件不得退化为复制房间邀请；按浏览器能力提供系统文件分享或明确不可用说明。
- [x] 区分对方已接收、文件链接已生成、已开始下载，不声称浏览器已经完成磁盘保存。
- [x] 添加设备统一邀请/输入配对码入口，简化远程加入，去除重复按钮和开发术语。
- [x] 设备/协作空间/中继/临时存储说明保持一致；更新同网络也可走 TURN 的说明和剪贴板临时保存说明。
- [x] 设置使用一致的保存/取消规则。
- [x] 空列表区分连接中、无设备和连接失败，提供邀请/重试动作。
- [x] 清理已完成保留失败任务及重试入口；传输结束后仍可进入任务历史。
- [x] 接收文件优先展示，移动端缩小发送区，保留跨工具任务提示；320px 下页签可读、结果操作使用文字。
- [x] 单元测试、类型检查、构建与浏览器关键路径回归通过。

## 回归场景

同网络不同房间不能收到白板；同空间成员可同步；接收方离线后不换人；文字粘贴/读取默认不发送；显式快捷模式可发送；直连文件分享不复制邀请；取消设置不改变偏好；断网不显示永久扫描；清理完成后仍能重试失败任务；窄屏接收保存入口优先且无横向溢出。

### 浏览器回归复现

在 `apps/admin-web` 中启动 `npm run dev -- --host 127.0.0.1 --port 5178 --strictPort`，另一个终端执行 `node scripts/transfer-ui-regression.mjs`。脚本需要可用的 Playwright 安装与 Chrome；可用 `PLAYWRIGHT_MODULE_PATH` 指向已有 Playwright 模块，或使用 `PLAYWRIGHT_CHANNEL` 指定已安装的兼容 Chromium 浏览器。

脚本使用隔离浏览器上下文，并模拟发现、鉴权、邀请和临时存储接口，不使用真实账号、不上传到线上。文件字节经过真实 WebRTC；这不是异地 NAT、真实 TURN 服务或生产对象存储的端到端验收。
