## 3. 两轮检查说明

### 3.1 第一轮：真实任务链检查

按用户实际完成流程图的顺序检查：

1. 打开空白文档。
2. 判断当前文档是否可编辑、是否已保存、是否处于协作状态。
3. 从图形库添加节点。
4. 选择、拖动、缩放和旋转节点。
5. 在节点之间建立连线。
6. 修改文字、颜色、尺寸和线条。
7. 框选多个元素并执行批量样式和排列。
8. 使用模板、页面、评论、版本和导入导出。
9. 在手机端重复图形插入、面板切换和属性修改。
10. 退出页面并判断未保存内容的保护能力。

### 3.2 第二轮：源码反向检查

从实现反查以下风险：

- UI 展示值是否真实代表全部选中对象。
- 控件是否会造成静默批量覆盖。
- 移动端隐藏能力是否有可发现入口。
- 触控热区是否足以完成精细操作。
- 保存、同步、权限是否使用相互独立的状态模型。
- 面板宽度、文字尺寸和默认展开策略是否适合专业编辑。
- 模板、图库和菜单是否具备渐进式信息架构。
- 页面离开、浏览器刷新和返回控制台是否有未保存保护。

两轮结果一致：当前最需要处理的不是继续堆叠功能，而是降低错误成本、减少界面遮挡，并让状态和命令更容易理解。

## 4. 当前界面基线

### 4.1 桌面端

- 顶部栏约 44px。
- 左侧图库固定 260px。
- 右侧设计属性固定 300px。
- 1440px 宽度下，两侧面板合计占 560px，约为视口宽度的 39%。
- 中间画布约 880px。
- 底部页面和状态栏约 36px。
- 右侧属性栏在没有选中元素时仍默认占用 300px。
- 小地图默认开启，即使空白文档也会显示。

### 4.2 手机端

- 顶部标题栏、面板切换栏和底部状态栏持续占用垂直空间。
- 顶部命令容器可见宽度约 131px，内部命令总宽度超过 430px。
- “排列、协作、视图、文件”等命令在首屏之外，只能横向滑动寻找。
- 右侧属性抽屉宽 300px，占 390px 视口约 77%，仅留下约 90px 画布。
- 工具栏和面板切换按钮多数高 32px。
- 桌面端画布操作提示在手机端通过 `sm:flex` 隐藏，手机没有等价的手势说明。

## 7. 详细问题

### UX-01 多选属性存在静默批量误改风险

优先级：P0

证据：

- `SyncedDiagram.tsx:5745-5798` 的 `updateSelection` 始终从 `cells[0]` 读取填充色、边框色、字体、线宽、透明度、旋转等属性。
- `SyncedDiagram.tsx:2823-2833` 的 `updateSelectedStyle` 将修改应用到全部可编辑选中元素。
- 属性面板没有“混合值”或“不一致”状态。
- `SyncedDiagram.tsx:4746` 在选区中只要包含一个锁定元素，就禁用整个属性 fieldset，与底层“跳过锁定元素”的批量处理语义不一致。

用户影响：

- 同时选择不同颜色的节点时，属性栏会显示第一个节点的颜色，用户容易误认为全部节点颜色相同。
- 用户修改线宽、字体或颜色后，全部选中元素被覆盖，原有视觉差异被静默破坏。
- 混合锁定选区中，属性面板完全不可编辑，但排列等操作可能继续跳过锁定元素，规则不统一。

建议：

- 为颜色、数字、选择框和开关增加 `mixed` 状态，显示为“—”或“混合”。
- 只有用户主动修改某个字段时，才把该字段批量应用到可编辑元素。
- 锁定使用三态：全部未锁定、部分锁定、全部锁定。
- 属性栏顶部显示“已选 N 个，M 个锁定”，并允许明确选择“仅修改未锁定元素”。

验收：

- 选择两个不同填充色节点时，填充色不得伪装成任一单一颜色。
- 未操作填充色字段时，修改字号不得改变原填充色差异。
- 混合锁定选区的规则与排列、删除、样式修改保持一致。

### UX-02 手机端核心命令隐藏在横向滚动区

优先级：P1

证据：

- `SyncedDiagram.tsx:4094` 使用 `overflow-x-auto` 和隐藏滚动条承载全部桌面菜单。
- 390px 视口中命令容器可见宽度约 131px，内部滚动宽度超过 430px。
- 首屏只能完整看到“编辑模式”和部分“编辑”菜单，“排列、协作、视图、文件”位于不可见区域。
- 页面没有渐隐、箭头、更多按钮或其他横向可滚动提示。

用户影响：

- 用户容易判断页面不支持导入导出、缩放适配、评论或版本。
- 横向滑动工具栏与画布手势存在认知竞争。
- 登录入口和公共工具占用右侧固定空间后，命令区进一步缩小。

建议：

- 手机端保留“编辑/只读”“撤销”“重做”或一个上下文操作。
- 其余命令合并到单一“更多”命令面板，按编辑、排列、协作、视图、文件分组。
- 支持命令搜索，但不要把命令搜索作为唯一入口。
- 桌面端继续保留现有菜单结构，不必与手机共用同一排布。

验收：

- 390px 宽度下不依赖横向滚动即可找到文件、视图和协作入口。
- 首次进入的用户能在两次点击内执行“适应画布”和“导出 PNG”。

### UX-03 手机属性面板遮挡绝大部分画布

优先级：P1

证据：

- `SyncedDiagram.tsx:4695` 的移动属性栏宽度为 `min(90vw, 300px)`。
- 390px 视口实测属性栏为 300px，仅留下约 90px 画布。
- `SyncedDiagram.tsx:7201-7207` 的 `InspectorSection` 没有折叠状态。
- 内容、位置、变换、外观、文字、泳道或连接线分组会连续展开。

用户影响：

- 修改填充、尺寸或文字时无法同时观察画布结果。
- 用户需要频繁关闭属性栏、查看结果、重新打开并滚动到原位置。
- 长属性面板在手机键盘弹出后可用高度进一步下降。

建议：

- 手机端改为底部面板，提供约 45% 和 85% 两个吸附高度。
- 默认展开“快速属性”，高级属性按内容、位置、外观、文字、连接线折叠。
- 底部面板半展开时保证画布中选中元素仍可见。
- 记住每个元素类型最近展开的分组。

验收：

- 手机修改颜色时至少保留 40% 可见画布。
- 切换属性分组不会丢失当前滚动位置和输入草稿。
- 键盘弹出后主要输入框和确认结果仍可见。

### UX-04 连线操作对触屏缺少可发现性

优先级：P1

证据：

- `SyncedDiagram.tsx:1531-1534` 只有约束处理器已获得焦点且存在当前约束时，才允许开始连线。
- `SyncedDiagram.tsx:1540-1542` 的锚点图像为 12 × 12，容差最小约 9。
- 桌面端依赖悬浮显示和十字光标；触屏没有稳定 Hover 状态。
- 手机端画布提示被隐藏，没有说明如何连接两个节点。

用户影响：

- 用户可以添加节点，但不知道从哪里开始连线。
- 即使看到锚点，也容易把连线操作识别为拖动节点。
- 小尺寸节点、缩小视图和高 DPI 手机上更难命中。

建议：

- 增加显式“连线模式”或节点选中后的四向连接入口。
- 视觉锚点可以保持 12–16px，但实际触控热区扩展到 36–44px。
- 第一次选中节点时展示一次轻量连接提示。
- 连线拖动开始后高亮可连接目标，并提供吸附反馈。

验收：

- 手机用户无需 Hover 即可开始连线。
- 390px 视口、100% 缩放下，连续建立五条连接不应频繁误拖节点。

### UX-05 编辑、协作和保存状态表达混杂

优先级：P1

证据：

- 顶部模式按钮表达“编辑模式/只读预览”。
- 非全屏介绍区使用“实时同步/本地编辑”，但完整编辑器顶部不持续展示同等级信息。
- `SyncedDiagram.tsx:3961-3967` 的账号菜单同时承担登录、云文档名称和未保存状态。
- `SyncedDiagram.tsx:4089-4090` 对未关联云文档的内容只显示“未命名流程图/专业流程图”。
- 操作状态栏会被最近一次普通操作消息覆盖，不适合作为持久状态来源。

用户影响：

- “实时同步”容易被理解为“已经保存”。
- 匿名用户不知道刷新、离开房间或所有协作者离线后内容是否仍可恢复。
- 登录用户无法一眼区分“房间同步完成”和“云端文件已保存”。

建议：

- 将状态拆成三个互不替代的维度：
  - 权限：编辑、只读、访客只读。
  - 协作：本地、连接中、已同步、同步中断。
  - 存储：仅临时、云端未保存、云端已保存。
- 文档标题附近固定显示存储状态。
- 协作者头像或人数附近固定显示协作状态。
- 状态栏继续承载操作反馈，不再承担持久状态解释。

验收：

- 用户不打开菜单即可判断当前内容是否已保存到云端。
- 房间连接正常但云端未保存时，两个状态必须同时且不冲突地显示。

### UX-06 云端未保存修改缺少离开页面保护

优先级：P1

证据：

- `cloudDirty` 已用于显示未保存状态，并在退出账号时触发确认。
- 当前前端代码没有 `beforeunload` 或路由离开拦截。
- 顶部“返回控制台”为直接链接，公共工具也可以直接切换页面。
- 云端保存为显式手动操作，没有自动保存机制。

用户影响：

- 用户编辑云端文档后点击返回、工具菜单或关闭标签页，可能在没有确认的情况下离开。
- 房间内同步状态可能让用户误认为云端文件已经保存。

建议：

- `cloudDirty` 为 true 时拦截浏览器关闭、刷新和应用内路由切换。
- 对应用内导航使用当前风格的确认弹窗。
- 对浏览器关闭和刷新使用标准 `beforeunload` 保护。
- 后续可增加节流自动保存，但不能用自动保存替代明确状态反馈。

验收：

- 云端文档产生未保存修改后，返回控制台、切换工具、刷新和关闭标签页均受到保护。
- 保存成功后不再弹出离开确认。

### UX-07 手机触控目标偏小且缺少操作帮助

优先级：P1

证据：

- `CompactPanelButton` 使用 `h-8`，即 32px 高。
- `DiagramToolbarButton` 和主要菜单入口同样使用 32px 高。
- 当前组件中存在大量 `h-8` 控件。
- `SyncedDiagram.tsx:4661` 附近的画布帮助通过 `hidden sm:flex` 在手机端隐藏。

用户影响：

- 图库、画布、属性等高频入口触控容错偏低。
- 用户无法从页面学习画布平移、缩放和连接线操作。
- 误触后通常会改变画布选择或关闭侧栏，恢复成本较高。

建议：

- 手机主要触控目标提升到至少 44px。
- 视觉图标可以保持小尺寸，但扩大按钮的真实热区。
- 首次进入提供一次可关闭的手机手势提示，之后可从帮助菜单重新打开。
- 不在画布上长期覆盖大段说明。

验收：

- 手机标题栏、面板切换和主要命令热区不低于 44px。
- 用户能从页面内找到平移、缩放、连线和框选的移动端说明。

### UX-08 固定双侧栏挤压桌面画布

优先级：P2

证据：

- `SyncedDiagram.tsx:4313-4316` 使用固定 `260px + 中间画布 + 300px` 网格。
- 没有选中元素时，设计属性栏仍显示空状态并占据 300px。
- 小于 1440px 的桌面或分屏窗口中，画布空间会快速下降。

用户影响：

- 大型流程图可见范围不足，需要更频繁地缩放和平移。
- 用户无法根据“搭结构”或“调样式”阶段调整空间分配。

建议：

- 图库和属性栏支持折叠、固定和拖动调宽。
- 未选择元素时可自动收起属性栏，但保留“固定显示”偏好。
- 低于 1280px 时默认只展开一个侧栏。
- 记住用户上次宽度和开关状态。

验收：

- 1280px 宽度下可获得至少约 65% 的画布宽度。
- 折叠和恢复侧栏不改变画布中心、缩放和选区。

### UX-09 属性面板缺少渐进披露

优先级：P2

证据：

- 所有 `InspectorSection` 默认展开且没有分组折叠状态。
- 普通矩形会连续展示内容、位置与尺寸、变换、外观、文字。
- 连线还会继续展示连接线设置。
- 高频属性和低频高级属性使用相同视觉权重。

用户影响：

- 查找常用颜色、字号或线型需要反复纵向扫描。
- 新用户被大量专业属性压迫，熟练用户又缺少快速入口。

建议：

- 属性栏顶部提供紧凑快速属性区。
- 内容、位置、外观、文字、连接线使用可折叠分组。
- 仅展开与当前选中类型最相关的分组。
- 增加“重置本组”和“复制/应用样式”入口，但避免重复已有顶栏命令。

验收：

- 修改填充色、边框色、字号和线型无需长距离滚动。
- 切换节点与连线时只展示适用属性。

### UX-10 图形库信息架构造成选择负担

优先级：P2

证据：

- 当前加载状态下可见约 44 个分类、9000 余个图形。
- 首屏同时出现快速模板、内置常用图形、流程图和完整图库入口。
- 图库总数徽标具有较高视觉存在感，但不能帮助用户选择。

用户影响：

- 新用户不知道应从模板、常用图形还是完整图库开始。
- 高频图形和低频专业图形的检索成本接近。
- 图形数量给人功能丰富的感觉，但也增加认知压力。

建议：

- 一级结构调整为“常用、最近、收藏、完整图库”。
- 搜索结果按常用、图形名称和所属分类分组。
- 支持固定收藏和最近使用。
- 图形总数降为辅助信息，不作为主要徽标。

验收：

- 最近使用过的图形可在一次点击内重新添加。
- 搜索同名图形时能够识别所属库和用途。

### UX-11 空白画布缺少首次操作入口

优先级：P2

证据：

- 空白文档中央没有开始面板。
- 用户需要主动理解左侧图库和顶部文件菜单。
- 当前帮助条主要描述快捷操作，而不是创建路径。

用户影响：

- 第一次使用时无法确定应拖拽、点击、导入还是选择模板。
- 强大的编辑器表现为空白画布和大量工具，学习成本被提前暴露。

建议：

- 空白画布中央提供“空白开始、选择模板、导入文件”。
- 插入第一个节点后自动消失。
- 登录用户可增加“打开最近文档”，但不把登录作为开始编辑的前置条件。

验收：

- 新用户进入空白文档后，最多两次操作即可创建第一个有效节点或打开模板。

### UX-12 模板缺少预览、落点和冲突处理

优先级：P2

证据：

- `SyncedDiagram.tsx:2398-2491` 根据当前视口计算中心位置后直接插入模板。
- 插入前没有检查目标区域是否已有元素。
- 三个快速模板以文字按钮展示，没有结构缩略图。

用户影响：

- 非空画布中模板可能覆盖现有元素。
- 用户点击前无法判断模板规模和结构。
- 模板插入当前页还是作为新页使用，语义不明确。

建议：

- 模板按钮展示真实缩略图。
- 点击后先显示幽灵预览，允许选择落点。
- 提供“插入当前页”和“创建新页面”。
- 默认落点执行简单碰撞检测和偏移。

验收：

- 模板不得无提示覆盖视口中心已有节点。
- 用户点击前能够识别模板的大致结构和规模。

### UX-13 菜单过长且缺少语义分组

优先级：P2

证据：

- 排列菜单在同一层列出组合、层级、分布、六种对齐和自动布局。
- 文件菜单在同一层列出导入、多种导出格式和清空文档。
- `DiagramToolbarMenu` 使用扁平项目数组，没有分隔组或子菜单结构。

用户影响：

- 常用命令与低频专业导出格式竞争注意力。
- 用户需要逐行扫描长菜单。
- 选择元素后仍需在顶栏和右侧栏之间往返。

建议：

- 排列菜单分为层级、对齐、分布、自动布局。
- 文件菜单分为导入、导出为、文档操作。
- 节点选中后提供轻量上下文工具条，只放颜色、连接、复制、锁定等高频操作。
- 撤销重做继续保留在编辑菜单，避免重新制造重复控制。

验收：

- 文件菜单首层不同时铺开全部导出格式。
- 选中节点后的四个最高频操作可在附近完成。

### UX-14 文档名称和页面管理入口不够直接

优先级：P2

证据：

- 标题只使用云端文档名，否则固定显示“未命名流程图”。
- 导入本地文件后标题仍可能保持“未命名流程图”。
- 新增、重命名、复制和删除页面全部收在“N 页”菜单中。
- “N 页”更像统计文本，不像页面操作入口。

用户影响：

- 多文档并行时难以确认当前文件身份。
- 用户不容易发现多页面能力。
- 新增页面比切换页面多一层不必要查找。

建议：

- 标题支持点击重命名，本地文档也保留临时名称。
- 导入文件后使用文件名作为建议名称。
- 页面标签旁提供明确的加号按钮。
- “N 页”菜单继续承载重命名、复制、删除等低频操作。

验收：

- 新增页面无需先理解“N 页”是菜单。
- 本地导入文档能够从标题识别来源。

### UX-15 全屏编辑时协作感知不足

优先级：P2

证据：

- `totalPeers` 的文字统计主要出现在非全屏介绍区。
- 完整编辑器顶栏的“协作”菜单没有人数徽标。
- 远程光标只有对方正在当前页移动时才可见。
- 房间状态、协作者列表、同步状态分别位于不同入口。

用户影响：

- 用户无法持续判断当前是否有人共同编辑。
- 网络中断和“暂时无人操作”在视觉上容易混淆。
- 进入评论、版本和房间成员需要先打开同一个笼统的协作菜单。

建议：

- 顶栏保存区附近展示紧凑头像堆叠或“协作 N 人”。
- 固定显示连接状态，但避免使用持续动画制造干扰。
- 协作菜单内再细分成员、评论和版本。

验收：

- 不打开菜单即可判断当前在线人数和同步是否正常。
- 当前页没有远程光标时，仍能识别房间中存在其他成员。

### UX-16 主要信息过度使用 10px 字号

优先级：P3

证据：

- `SyncedDiagram.tsx` 当前有约 66 处 `text-[10px]`。
- 图库说明、属性标签、状态、评论、版本和移动端统计大量使用相同小字号。
- 图形详情在 CSS 中仍使用 9px。

用户影响：

- 中文小字号在普通 Windows 缩放和手机屏幕上扫描成本较高。
- 标题、字段标签和辅助说明之间的层级差异不足。
- 界面看似紧凑，但阅读速度下降。

建议：

- 主要控件和字段正文提升到 12–13px。
- 11px 仅用于辅助元数据，10px 仅用于徽标或极短状态。
- 通过删除重复副标题、折叠低频属性保持紧凑，而不是继续缩小文字。

验收：

- 手机和 125% Windows 缩放下无需额外浏览器缩放即可阅读主要控件。
- 字段名、值、辅助说明具有明确层级。

### UX-17 命令按钮过度使用胶囊形

优先级：P3

证据：

- `index.css:3940-3945` 将工具栏按钮、菜单、紧凑按钮、主按钮和属性操作统一为 `border-radius: 999px`。
- 模式切换、普通命令、菜单入口和属性操作因此使用相近轮廓。

用户影响：

- 命令与状态、模式选择之间缺乏形态区分。
- 多个胶囊连续排列时，桌面编辑器更像筛选器集合，不像专业工具栏。

建议：

- 胶囊仅用于状态、模式和分段选择。
- 普通命令采用 6–8px 圆角。
- 熟悉图标按钮保持圆形。
- 危险命令主要依靠文案、颜色和确认表达，不依靠特殊圆角。

验收：

- 用户能从轮廓快速区分模式、状态和一次性命令。
- 保持 Apple 风格的克制感，但不牺牲工具属性。

### UX-18 小地图未根据内容范围自适应

优先级：P3

证据：

- `SyncedDiagram.tsx:982` 默认 `showMinimap = true`。
- 空白文档和只有少量节点的文档也会在桌面显示小地图。
- 小地图覆盖画布右下区域，与画布帮助和选区操作竞争空间。

用户影响：

- 简单流程图中小地图没有导航价值。
- 画布可用空间被持续占用。

建议：

- 文档内容超出当前视口一定比例后再自动显示。
- 用户手动开启或关闭后记住偏好。
- 空白文档默认隐藏。

验收：

- 空白和单屏可容纳的简单文档不默认显示小地图。
- 大图超出视口后可以快速打开或自动出现。

## 9. 建议实施顺序

### 第一阶段：避免误改和任务失败

1. UX-01 多选混合值和混合锁定。
2. UX-06 未保存离开保护。
3. UX-05 权限、协作、存储三类状态拆分。
4. UX-02 手机命令结构。
5. UX-03 手机属性底部面板。
6. UX-04、UX-07 触屏连线和触控热区。

阶段目标：

- 不再发生属性栏伪装单一值造成的静默批量覆盖。
- 手机端不依赖隐藏横向滚动完成主要任务。
- 云端未保存内容不会无提示离开。

### 第二阶段：提升专业编辑效率

1. UX-08 可调整侧栏。
2. UX-09 渐进式属性面板。
3. UX-10、UX-11 图库与空白文档入口。
4. UX-12 模板预览和碰撞处理。
5. UX-13 命令分组和上下文工具条。
6. UX-14 文档标题和页面入口。
7. UX-15 协作状态常驻。

阶段目标：

- 桌面画布空间可以随任务阶段调整。
- 高频操作减少在顶栏、画布、右侧栏之间的往返。
- 新用户能快速开始，熟练用户能快速复用。

### 第三阶段：视觉和自适应收敛

1. UX-16 字号层级。
2. UX-17 控件形态。
3. UX-18 自适应小地图。

阶段目标：

- 保留当前安静的 Apple 风格。
- 紧凑来自信息归并和渐进披露，而不是依靠过小字号。

## 10. 总体验收清单

### 桌面端

- 1280、1440、1920 三档宽度下，画布、图库和属性栏不会互相挤压失衡。
- 多选不同样式元素时，属性栏显示混合状态。
- 未选择元素时可以快速释放属性栏空间。
- 模板不会无提示覆盖现有元素。
- 在线人数、同步状态和保存状态同时可见且语义独立。
- 云端未保存状态下离开页面会得到保护。

### 手机端

- 390 × 844 下不使用横向隐藏工具栏。
- 主要触控目标不低于 44px。
- 属性编辑时至少保留 40% 画布可见。
- 不依赖 Hover 即可建立节点连线。
- 图库、画布、属性和更多命令之间切换不会丢失选区。
- 手机键盘弹出后，正在编辑的字段和结果仍可见。

### 可理解性

- 新用户在两次操作内创建第一个节点或插入模板。
- 用户能明确区分“实时同步”和“已经保存”。
- 用户能从标题识别当前文档，从页面栏直接新增页面。
- 常用图形、最近图形和收藏图形可以快速访问。

## 14. 第二轮独立复查与修复（2026-07-25）

对第 13 节声称已完成的 18 项做独立代码级复查，并寻找此前未覆盖的维度。
本轮以静态代码审查为主，修复后用浏览器实测复核（`#diagram` 独立页，1280×720）。

### 14.1 复查方法与一处方法论教训

首轮筛查我用 `grep -cE "guide\|Guide"` 之类的写法批量探测能力缺失。**这是错的**：
`-E`（扩展正则）下 `\|` 是**字面竖线**而非"或"，三条探测（参考线、吸附、网格开关）
全部返回 0，导致我一度判定"无智能对齐参考线"。改用正确语法复核后证伪——
`SelectionHandler.guidesEnabled = true` 早已设置，`setGridEnabled(true)` 亦然，
底栏还有"拖动时会显示智能参考线"的提示。

**结论：该项不成立，未做任何"修复"。** 记录于此以免后续重复误判。

### 14.2 本轮确认并修复的问题

| 编号 | 问题 | 类型 | 状态 |
| --- | --- | --- | --- |
| R-01 | 英文 Error 消息被推断为中性色，真实失败看起来像普通提示 | 体验 | DONE |
| R-02 | 引导性约束提示（"至少需要两个节点"）被判为错误显示告警色 | 体验 | DONE |
| R-03 | 状态栏 `truncate` 截断长反馈且无法查看全文 | 界面 | DONE |
| R-04 | 字号修复依赖脆弱的 `!important` 覆盖，且有三处遗漏 | 界面/可维护 | DONE |
| R-05 | 全局 keydown 无焦点作用域，内嵌模式下 Delete 有误删风险 | 体验 | DONE |
| R-06 | 网格吸附无关闭入口，无法做像素级微调 | 功能 | DONE |

#### R-01 / R-02 状态语气不可信

`inferDiagramStatusTone` 靠中文关键词正则推断语气，而 19 处错误路径写作
`setStatus(error instanceof Error ? error.message : "…失败")`。浏览器与第三方库抛出的
`Error.message` 多为英文（`Failed to fetch` 等），匹配不到中文关键词即退化为 `info`，
导出失败、云端保存失败会以与"已复制"相同的中性灰呈现，极易被忽略。

反向问题同样存在：正则含 `请先|至少需要|已忽略|已锁定`，把"至少选择两个节点才能对齐。"
这类正常引导语判成 `error` 显示告警色，稀释真错误的信号价值。

修复：19 处错误调用点全部显式传入 `"error"`；正则移除引导类关键词，降级为纯兜底并加注释
说明调用点应显式指定语气。实测 `Failed to fetch` 不再依赖推断，引导语回归 `info`。

#### R-03 状态截断无法读全

状态栏为 `min-w-0 flex-1 … truncate` 且无 `title`。"已清空可删除内容，保留 3 个锁定元素。"
这类含关键数量的反馈会被截断，用户无从得知保留了几个。修复：补 `title={status}`。

#### R-04 字号修复方式脆弱

第 13 节 UX-16 声称"统一提升为至少 11px"，实际是通过
`.diagram-apple .text-\[10px\] { font-size: 11px !important }` 全局覆盖实现的——
运行时确实是 11px（我最初据源码判断"未修复"是错的），但存在四个隐患：
源码仍是 55 处 `text-[10px]` 会误导维护者继续扩散；`text-[9px]` 3 处无对应覆盖；
`.diagram-apple-palette-detail` 与 `.diagram-apple-count-badge` 被显式钉死 10px 未受益；
覆盖依赖 Tailwind 任意值类名的转义选择器，组件移出作用域即静默回退且无测试守护。

修复：源码 55 处改为实值 `text-[11px]`、3 处 `text-[9px]` 提到 10px（其中菜单分组标签
进一步提到 11px），移除 CSS 覆盖，`palette-detail` 与 `count-badge` 提到 11px
（badge 同步 `min-height` 20→22px 以容纳）。实测编辑器内仅剩头像首字为 10px
（24px 圆内的单字缩写，刻意保留）。

#### R-05 快捷键缺焦点作用域

`window.addEventListener("keydown")` 仅由 `isActive` 与输入类选择器黑名单守卫。
组件在 `PublicTransferPage` 以**非 standalone 内嵌**方式使用，用户点击页面其它非输入区域
后按 `Delete`/`Backspace` 仍会删除画布元素，按 `Ctrl+A` 会接管选区。

修复：破坏性与选区类快捷键（Delete/Backspace、⌘A/Z/Y/X/V/D/C、Enter/F2、方向键）
增加焦点包含判断——全屏或独立页保持全局响应，内嵌模式要求焦点位于编辑器内。
画布已有 `tabIndex={0}` 且 `onPointerDown` 主动 `focus()`，点击即可获得焦点，不影响正常使用。

实测：焦点在编辑器外按 Delete，节点数保持 1 不变；聚焦画布后按 Delete，
状态显示"已删除 1 个选中元素。"且节点数归零。

#### R-06 网格吸附无法关闭

网格吸附（10px）默认开启且无关闭入口，贴合边界或像素级微调时元素无法停在网格之间。
修复：视图菜单新增「对齐到网格」开关，状态持久化到 `diagram-grid-snap`，
graph 初始化时读取该偏好。实测切换后状态提示"已关闭对齐到网格，可自由微调位置。"，
偏好写入 localStorage。
